# Lovely Eye v2.0.0

Version 2.0 is a coordinated reliability, analytics-accuracy, security, UI, architecture, and
dependency release. It is a major release because externally observable tracker and browser-session
contracts changed. Existing analytics data is preserved, but operators must review the checks below
before replacing a v1 container.

## Upgrade impact

Action is required before deployment:

1. Back up the SQLite or PostgreSQL database.
2. Pin `ghcr.io/revotale/lovely-eye:v2.0.0` instead of deploying `latest`.
3. Verify every explicitly set environment value. Invalid booleans, integers, durations, log levels,
   database settings, CIDRs, and limits now stop startup with an actionable error instead of silently
   falling back to defaults.
4. If a public CDN or another proxy connects to Lovely Eye from public IP ranges, set
   `TRUSTED_PROXY_CIDRS` to those exact ranges. Private Docker, loopback, and IPv6 unique-local ranges
   remain trusted by default.
5. If the standard tracker is loaded from this Lovely Eye instance, no snippet replacement is needed.
   If the tracker was copied, vendored, or reimplemented, replace it with the v2 tracker contract
   before or atomically with the server upgrade.

Follow the complete [upgrade and rollback procedure](https://github.com/RevoTale/lovely-eye/blob/v2.0.0/UPGRADING.md).

## Breaking changes

### Tracker and analytics semantics

- `POST /api/collect` takes `site_key` only from the query string.
- Page views send `path` and optional first-touch attribution. Exit pings send `path` plus `exit: true`.
- Client-provided `duration`, `screen_width`, client/session IDs, and body-level `site_key` are no
  longer part of the accepted contract. Session timing and identity are server-owned.
- SPA history changes remain automatic. Use `window.lovelyEye.track()` for an explicit current-path
  page view or `window.lovelyEye.track({ name, properties })` for an allowlisted custom event.
- The tracker uses `text/plain;charset=UTF-8` for beacon-safe cross-origin collection.
- Visitor, page, referrer, session-duration, and bounce-rate results may differ from v1 because v2
  fixes counting boundaries and rejects client-controlled timing. This is an intentional accuracy
  change, not a destructive rewrite of historical rows.

The exact payload examples and session rules are in
[ANALYTICS.md](https://github.com/RevoTale/lovely-eye/blob/v2.0.0/ANALYTICS.md).

### Authentication and URLs

- Authentication cookie names and paths are scoped to the normalized runtime `BASE_PATH`. Existing v1
  browser sessions must sign in once after the upgrade. This prevents multiple Lovely Eye instances
  on one origin from sharing credentials accidentally.
- Analytics and site settings now have separate dashboard routes. Old internal dashboard bookmarks
  are not redirected; open the dashboard root and select the site again.
- The bundled dashboard and GraphQL schema are released atomically. The GraphQL endpoint remains an
  internal dashboard contract, not a versioned external API.

### Configuration

- Auth and analytics rate limiting is enabled by default.
- Request-body, GraphQL-complexity, date-range, filter-count, and filter-length limits now have strict
  validated configuration.
- Forwarded client IP headers are honored only from `TRUSTED_PROXY_CIDRS`. This can change visitor
  identity, GeoIP, IP blocking, and rate-limit behavior if a public proxy range is omitted.
- `JWT_SECRET` and `ANALYTICS_IDENTITY_SECRET`, when set, still require at least 32 characters. Keep
  their current values to preserve sessions and analytics identity continuity.

## Data and migrations

- No existing analytics, users, sites, domains, event definitions, or configuration rows are deleted
  or require reimport.
- The only new database migration adds analytics query indexes for both SQLite and PostgreSQL. It has
  tested up and down paths and does not rewrite domain data.
- The server applies pending migrations automatically before opening the HTTP service. Index creation
  needs temporary disk and I/O headroom; schedule a normal maintenance window for large databases.
- The v2 schema remains usable by v1.7 because the new migration is index-only. A fast image rollback
  can therefore retain the migrated database, but it cannot undo analytics collected under v2
  semantics. Use the pre-upgrade backup for a full point-in-time rollback.

## What users gain

- Exact dashboard totals and lower database query fan-out.
- Server-owned session timing, safer proxy address handling, bounded public endpoints, stable GraphQL
  errors, security headers, and production-disabled GraphQL playground.
- A feature-owned Go modular monolith and strict frontend feature boundaries without legacy layers.
- A rebuilt shadcn/Tailwind admin UI with stable loading states, responsive layouts, improved site
  creation recovery, separate analytics/settings navigation, and the Zen Inspired theme.
- One dashboard build that works at `/`, `/lovely-eye`, and nested runtime base paths.
- Current stable Go, Bun, Vite, React, GraphQL, shadcn, PostgreSQL, Docker bases, and CI tooling.

## Compatibility and verification

- Container platforms: `linux/amd64` and `linux/arm64`.
- Databases: SQLite and PostgreSQL; the release matrix uses PostgreSQL 18.6.
- Runtime mounts: root and arbitrary nested `BASE_PATH` deployments.
- Verified gates include strict frontend types, Biome, Go lint/tests, generated-code freshness,
  browser admin flows, three runtime-base-path deployments, same-origin auth isolation, SQLite and
  PostgreSQL migration up/down/reapply, race tests, production container health, dependency audits,
  and performance budgets.

The published GitHub Release includes the exact multi-architecture image digest. Use that digest
when deployment reproducibility is more important than following a patch or major channel.

## Known residual findings

- Production Bun dependencies and reachable Go packages have no known reported vulnerabilities in
  the release audit.
- A dev-only `picomatch` advisory remains behind build-tool dependency edges that Bun cannot safely
  override without affecting incompatible consumers.
- `golang.org/x/crypto/openpgp` has a module-level advisory, but Lovely Eye does not import the package
  and no fixed module release exists. See the
  [security register](https://github.com/RevoTale/lovely-eye/blob/v2.0.0/docs/security.md).
